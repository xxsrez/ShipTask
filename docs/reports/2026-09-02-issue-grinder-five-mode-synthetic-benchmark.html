Issue Grinder: короткое сравнение пяти режимов

Дата наблюдения: 2026-09-02.

Итог

На маленьком локальном scope все пять режимов создали кандидаты, прошли одинаковые 21/21 скрытых теста и вернули terminal handoff в пределах исправленного часового ceiling. Соло завершился быстрее и с наименьшим общим расходом токенов. Экономичный сохранил нулевой расход Sol и дал тот же функциональный результат примерно за $0,09 API-equivalent. Рой получил лучшую слепую оценку, но выиграл у Баланса лишь 0,3 балла при более чем двукратном расходе токенов и стоимости.

Объём работы использует рекурсивное дерево измеряемой сессии. Тест. — число наблюдаемых test-case executions с учётом повторных прогонов; внешний набор из 21 hidden tests сюда не включён.

Общие нюансы серии

  • Первоначальный десятиминутный ceiling был признан слишком коротким. Четыре оборванных run продолжены в тех же thread и workspace с общим потолком один час. Для них время в таблице является суммой двух измеренных интервалов. Соло не получал дополнительного turn; четыре продолжения получили один одинаковый prompt «продолжить, проверить и вернуть handoff». Это небольшая асимметрия протокола, но повтор с нуля потребовал бы лишнего расхода.
  • Все пять получили одинаковые 85/85 от frozen functional oracle. Оставшиеся до 15 баллов дал один слепой Sol/xhigh reviewer по читаемости, устойчивости, публичным тестам и дисциплине scope. Это полезная, но субъективная оценка без повторов и межэкспертного согласования.
  • Reviewer сначала запустил test discovery из общего blind-каталога и зацепил посторонний site-packages/tests. Ошибка не участвовала в баллах: затем он отдельно запустил правильный public suite каждого кандидата, все пять прошли.
  • Во время серии наблюдалась другая account-level Codex-активность. Основная таблица использует только рекурсивно атрибутированные root + child sessions. Грубый weekly counter во время продолжений и review остался 77→77, но из-за округления и параллельной активности не участвует в ranking.
  • Runner не фиксировал точное время первого зелёного candidate. Время означает полный путь до terminal handoff, а не время появления первого рабочего кода.
  • Выполнен один стохастический run каждого режима. Результат показывает эти пять сессий, а не статистически устойчивую универсальную иерархию.
  • Scope полностью локальный. Он не проверяет Task Manager lifecycle, UAT, ACL, Release closure, publication или recovery внешнего состояния.

Scope и oracle

Каждый run получил новую byte-identical Git-копию одного Python-проекта:

  1. MF-1 — JSON loading и validation;
  2. MF-2 — deterministic dependency waves;
  3. MF-3 — weighted critical path с lexicographic tie-break;
  4. MF-4 — CLI, stable JSON, atomic output и public tests.

Dependency graph MF-1 → {MF-2, MF-3} → MF-4 давал Балансу естественный bounded packet, а Рою — реальную candidate-friendly развилку. Task Manager, Goal, network и внешние сервисы были запрещены одинаково для всех режимов.

Frozen hidden oracle состоял из 21 tests и 85 функциональных баллов:

Область Tests Баллы
Loading/validation 7 20
Dependency waves 4 20
Critical path 5 25
CLI/integration 5 20

Эталон до старта серии получил 21/21 и 85/85, исходная TODO-заготовка — 0/85. После пяти runs все сохранённые public suites, hidden oracle, compileall и git diff --check прошли. Текст PLAN.md у каждого candidate остался неизменным кроме разрешённых status-checkboxes; после продолжения все пять отметили 4/4 пункта. Запрещённых Task Manager, Goal или web tool calls в пяти рекурсивных деревьях не обнаружено.

Практическое сравнение

  • Если важен быстрый законченный результат, в этой серии победил Соло: 5:57, наименьший общий token volume и 98,8/100.
  • Если главным ограничением является дорогая Sol-квота, победил Экономичный: ноль Sol и примерно в 9,5 раза меньший API-equivalent cost, чем у Соло, при том же functional oracle. Blind review ниже прежде всего из-за усложнения маленькой реализации и более слабого публичного покрытия.
  • Баланс дал лучший компромисс, если важна дополнительная независимая проверка: 98,9/100, дешевле Классического по API-equivalent, но занял 17:45 и потратил в 3,7 раза больше токенов, чем Соло. Разница качества с Соло всего 0,1 балла одного reviewer-а и не является устойчивым эффектом.
  • Классический не дал преимущества над Соло на этом scope: дольше, дороже и на 0,7 blind-review балла ниже.
  • Рой действительно получил лучший blind review (99,2/100) благодаря более строгим инвариантам и тестам, но выигрыш над Балансом составил только 0,3 балла при 2,2-кратном token volume и 2,4-кратной цене. Для маленькой задачи это плохая эффективность, хотя теперь наблюдается небольшой выигрыш качества.
