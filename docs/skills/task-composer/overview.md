# Task Composer: обзор

Статус: действующий пользовательский Overview, 2026-09-02.

Этот документ определяет общий смысл Task Composer: что это за сущность, для
кого она существует и зачем мы её разрабатываем. Он принадлежит пользователю и
меняется только по его явному указанию. Конкретные обязательные свойства
находятся в Requirements, а способ их достижения — в Architecture.

## Что это

Task Composer — skill, который превращает замысел и требования человека в
связную, понятную и исполнимую модель работы в Task Manager. Он определяет,
достаточно ли одной Task или нужен Epic с самостоятельными подзадачами, и
сохраняет общий результат, существенные границы и ожидаемые доказательства так,
чтобы работу можно было осознанно проверить и передать в исполнение.

Task Composer отвечает за качество постановки и декомпозиции, а не за саму
разработку. Созданный им план остаётся planning-моделью: реализация, проверка,
выпуск и управление delivery lifecycle принадлежат другим workflow.

## Для кого он существует

Skill предназначен для человека или команды, которым нужно превратить идею,
проблему или крупный результат в Task Manager scope без ручного составления
каждой технической карточки и без потери исходного смысла.

Пользователь определяет, чего нужно достичь и какие границы существенны. Task
Composer берёт на себя инженерную конкретизацию: выбирает полезный масштаб
Tasks, формирует целостный Epic при необходимости и делает каждую часть
достаточно самостоятельной для будущего исполнителя.

## Какую пользу он даёт

Task Composer создаёт план, который одновременно сохраняет замысел человека и
пригоден для автономной инженерной работы. Он уменьшает риск формальной
декомпозиции, скрытых пробелов, потерянных зависимостей и Tasks, понятных только
автору первоначального обсуждения.

Коротко: Task Composer превращает требования человека в качественно
сформулированный Task Manager scope, готовый к проверке и последующей передаче
в delivery.
