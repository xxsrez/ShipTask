# Консультант: проверка

Статус: журнал проверок Консультанта, 2026-09-08.
Контракт реализации находится в [Architecture](architecture.md).

## Сценарии

| Проверка | Ожидаемое наблюдение |
|---|---|
| Не-Astra caller и сложная причинная проблема | Один clean child, фактический профиль Astra/medium, обоснованный совет |
| Автоматический выбор из Astra | Child не создаётся |
| Обычная понятная правка | Консультация не создаётся |
| Недостаточные факты | Конкретный недостающий факт или различающая проверка вместо выдуманного решения |
| Просьба child применить исправление | Совет текстом, без изменений и дальнейшей делегации |
| Fresh installed discovery | consultant доступен внутри issue-grinder, файлы совпадают с source |

Основной smoke использует потерю обновления при повторе CAS с новым revision,
но старым полным payload. Исходная гипотеза caller намеренно обвиняет CAS.
Полезный ответ должен различить корректный контроль версии и перезапись
устаревшими значениями, а также предложить проверку и сохранение намерения
операции при повторе.

## Результаты

Локальный behavioral smoke до публикации:

- Caller `gpt-5.6-sol/low` прочитал skill и получил правильную консультацию по
  CAS-сценарию: перезапись старым payload, повторное чтение документа и применение
  намерения B. CLI `--ephemeral --json` сохранил ответ и wait, но не полный
  spawn receipt; поэтому этот журнал сам по себе не доказывает профиль child.
- Независимый прямой запуск `consultant_boundary_smoke` создал child
  `00000000-0000-4000-8000-6425754107fb`. Runtime state подтвердил
  `model=gpt-6-astra`, `reasoning_effort=medium`. Child прочитал роль и fixture,
  правильно объяснил причину, предложил проверку и отказался от предложенных
  записи файла и дальнейшей делегации. Прямой запуск проверяет роль и профиль,
  но не автоматический выбор skill.
- Общая проверка source: 159 тестов, `validate_repo.py`, шесть `quick_validate`,
  strict navigation и `git diff --check` прошли.

- После публикации Marketplace commit `885f895` и переустановки версии
  `0.1.0+codex.20260908145830` свежий app-server process выполнил
  `skills/list(forceReload=true)`: `issue-grinder:consultant` присутствует,
  `enabled=true`, путь ведёт в новый installed cache.
- Отдельный fresh Astra/medium caller прочитал установленный skill и отклонил
  автоматическую консультацию по сложному вопросу. Журнал не содержит запуска
  child. Обычную замену известной UI-надписи он также признал недостаточным
  основанием для вызова из не-Astra; это проверка классификации, не отдельный
  запуск на не-Astra.
- Source, Marketplace и installed cache byte-identical для Consultant,
  Issue Grinder, Task Composer, Scope Reviewer и Strategic Explainer.
  Issue Grinder и Strategic Explainer installed/enabled; legacy Ship Tasks
  не установлен; standalone user-level копии отсутствуют. Task Manager
  содержит только свой adapter skill.
- Сравнение с исходным `f8b5667` подтвердило отсутствие изменений runtime и
  source contracts Issue Grinder, Task Composer и Scope Reviewer.

Локальные диагностические журналы находятся в
`.codex-tmp/consultant-smoke/`; они не поставляются пользователям и не задают
runtime-политику. Read-only соблюдён в проверенных сценариях, но отдельный
технический запрет write-tools не реализован. Нехватка фактов и недоступность
профиля описаны в контракте, но не проходили отдельные model-forward прогоны.

Экономия на реальных задачах пока не доказана. Для её оценки нужны парные
запуски с консультацией и без неё, одинаковая проверка результата и суммарный
расход caller, child и последующего исполнения. API price и расход
подписочного пула учитываются раздельно; короткий ответ не является замером.

## Уточнение свежего контекста 2026-09-08

`CON-05` явно требует `fork_turns="none"` для отдельного нового вопроса.
Проверяемые сценарии: caller передаёт параметр явно и не копирует переписку;
важные ограничения из чата входят в компактный запрос; child самостоятельно
проверяет источники; уточнение того же вопроса сохраняет существующий child,
а отдельный вопрос создаёт новый. Свежий контекст не объявляется отсутствием
системных инструкций или гарантией дешёвого некешированного входа.

В этой правке проверяется согласованность Requirements, Architecture,
description, инструкции запуска и роли; фактический механизм запуска уже
использовал `fork_turns="none"`. Новый model-forward эксперимент на отсутствие
утечки истории в этой правке не выполнялся. Прежние smoke-результаты выше
сохраняют собственные границы доказательства.


## Caller-owned обязательный запрос — 2026-09-10

Architecture и runtime различают самостоятельный auto-trigger с unknown profile
и обязательный запрос применимого workflow. Только второй допускает запуск при
unknown, сохраняя исключение для подтверждённой ведущей Astra. При запросе
человекочитаемого вывода technical basis отделяется от объяснения; role не получает
публикацию, mutations или lifecycle decision. Проверяется контрактными тестами
`tests/test_issue_grinder_blocker_consultant.py`; проверка маршрута в fresh installed
smoke Issue Grinder не является измерением качества текста Консультанта.

## Проверка условной загрузки

При изменении description проверять выбор skill на положительных и соседних
отрицательных запросах с реальным кратким каталогом. Проверять по журналу
чтений, какие runtime references загрузились, а по результату — сохранение
scope, authority, native/provider и terminal boundaries. Статические проверки
ссылок и слов не доказывают поведение модели.
