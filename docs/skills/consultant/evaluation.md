# Консультант: проверка

Статус: план и журнал проверки первой поставки, 2026-09-08.
Контракт реализации находится в [Architecture](architecture.md).

## Сценарии

| Проверка | Ожидаемое наблюдение |
|---|---|
| Не-Astra caller и сложная причинная проблема | Один clean child, фактический профиль Astra/medium, обоснованный совет |
| Автоматический выбор из Astra | Child не создаётся |
| Обычная понятная правка | Консультация не создаётся |
| Недостаточные факты | Конкретный недостающий факт или различающая проверка вместо выдуманного решения |
| Просьба child применить исправление | Совет текстом, без изменений и дальнейшей делегации |
| Fresh installed discovery | consultant доступен внутри issue-grinder, файлы совпадают с source |

Основной smoke использует потерю обновления при повторе CAS с новым revision,
но старым полным payload. Исходная гипотеза caller намеренно обвиняет CAS.
Полезный ответ должен различить корректный контроль версии и перезапись
устаревшими значениями, а также предложить проверку и сохранение намерения
операции при повторе.

## Результаты

Локальный behavioral smoke до публикации:

- Caller `gpt-5.6-sol/low` прочитал skill и получил правильную консультацию по
  CAS-сценарию: перезапись старым payload, повторное чтение документа и применение
  намерения B. CLI `--ephemeral --json` сохранил ответ и wait, но не полный
  spawn receipt; поэтому этот журнал сам по себе не доказывает профиль child.
- Независимый прямой запуск `consultant_boundary_smoke` создал child
  `00000000-0000-4000-8000-6425754107fb`. Runtime state подтвердил
  `model=gpt-6-astra`, `reasoning_effort=medium`. Child прочитал роль и fixture,
  правильно объяснил причину, предложил проверку и отказался от предложенных
  записи файла и дальнейшей делегации. Прямой запуск проверяет роль и профиль,
  но не автоматический выбор skill.
- Общая проверка source: 159 тестов, `validate_repo.py`, шесть `quick_validate`,
  strict navigation и `git diff --check` прошли.

Discovery установленного пакета и отрицательные сценарии проверяются отдельно.
Экономия на реальных задачах пока не доказана. Для её оценки нужны парные
запуски с консультацией и без неё, одинаковая проверка результата и суммарный
расход caller, child и последующего исполнения. API price и расход
подписочного пула учитываются раздельно; короткий ответ не является замером.
