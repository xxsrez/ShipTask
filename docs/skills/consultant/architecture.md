# Консультант: архитектура

Статус: текущая agent-owned Architecture, 2026-09-08.

Пользователь согласовал предложенные Requirements и поручил реализацию и
публикацию 2026-09-08. Первоначальные user-owned [Overview](overview.md) и
[Requirements](requirements.md) сохранены без редакционной перезаписи, включая
их исторические отметки черновика. Новое ограничение текущей поставки:
Консультант доступен отдельно, интеграция в процесс Issue Grinder не выполняется.

## Runtime и упаковка

Единица runtime — каталог `consultant/`, поставляемый как
`plugins/issue-grinder/skills/consultant/`. Короткий `SKILL.md` обеспечивает
обнаружение, отбор обращений и запуск. `references/consultant-role.md` задаёт
терминальную роль советчика. Вместе они компилируют три независимых source-входа
этого каталога; соседние entities не являются скрытым источником политики.

Отдельного устанавливаемого глобально `agent_type=consultant` нет. Документированный
custom-agent механизм использует `~/.codex/agents/` или `.codex/agents/`, тогда
как проверенный plugin manifest предоставляет skills, MCP и hooks. Поэтому
пакет запускает встроенный `default` child через `collaboration.spawn_agent`:
`model="gpt-6-astra"`, `reasoning_effort="medium"`, `fork_turns="none"`.
Фиксированные параметры входят в вызов инструмента; упоминание Astra в тексте
без этих параметров не является реализацией профиля.

Основания выбора формы, проверенные 2026-09-08:
[custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents),
[plugin architecture](https://developers.openai.com/plugins/concepts/plugins).
`agents/openai.yaml` — только UI metadata, не определение модели субагента.

Никакие файлы `issue-grinder/`, `task-composer/`, `scope-reviewer/` и их source
contracts ради этой поставки не меняются. Отдельная доступность skill не
назначает консультацию этапом, проверкой или исключением из topology гриндера.
При действующем workflow его ограничения сохраняются; skill их не обходит.

## Один цикл консультации

1. Caller проверяет собственную модель и основания обращения. Автоматический
   вызов из Astra пропускается; явное обращение пользователя допускается.
   Неопределённый профиль нельзя выдавать за подтверждённую не-Astra модель.
2. Caller формулирует один вопрос, цель, ограничения, факты, проверенные
   гипотезы и точные anchors. Подготовка не требует нового полного исследования.
3. Caller напрямую вызывает `collaboration.spawn_agent` с фиксированным
   профилем выше, уникальным task name и абсолютным путём к файлу роли из
   фактически загруженного skill. В задаче child стоит маркер
   `CONSULTANT_READ_ONLY_V1`; он обозначает роль, не является секретом или
   механизмом безопасности. История caller не наследуется.
4. Child читает только файл роли и адресно нужные источники, возвращает совет,
   основания, ограничения уверенности и следующую различающую проверку либо
   конкретный недостающий факт. Полезные примеры кода допустимы в ответе.
5. Caller получает результат штатными средствами collaboration, оценивает
   применимость и сам выполняет проверку. При уточнении передаёт новые факты в
   существующий child без переопределения профиля. Без нового основания
   повторный запрос не создаётся.

При недоступном tool, неподдерживаемом профиле или ошибке запуска caller
сообщает недоступность консультации. Он не подменяет её собственной репликой
от имени Astra, другой моделью, CLI-процессом или отдельной app task.
Это ограничение runtime; изолированные CLI-проверки самого пакета при разработке
не являются альтернативным transport консультации.

## Read-only и стоимость

Запрет изменений и дальнейшей делегации находится непосредственно в роли,
включая случай просьбы caller применить исправление. Инструменты могут
наследоваться от parent; этот пакет не заявляет отдельный технический sandbox
или отключённые write-tools. Проверка отсутствия изменений относится к
наблюдаемому поведению, а не к гарантии платформенного запрета записи.

Экономия достигается отбором вопросов, отсутствием унаследованной истории,
адресным чтением и прекращением анализа после достаточной рекомендации.
Ограничение длины ответа не считается ограничением reasoning. Не вводятся
выдуманные жёсткие token caps и обязательный большой отчёт.

Подписочную экономику нельзя выводить из API-прайса. Для пользователя актуальная
локальная калибровка из `codex-token-usage-report` даёт ориентир около 3,84× Sol
для входа/кеша и 3,20× для выхода на Pro 20x, по наблюдениям 4–6 сентября 2026.
Это контекст оценки, не переносимый тариф runtime. Числа не зашиваются в skill:
он сообщает только, что Astra дорогая и пользу надо соотносить с расходами.

## Трассировка и оценка

| Source | Runtime | Наблюдение |
|---|---|---|
| Overview: сильный советчик при экономном основном исполнении | Короткий skill и отдельный child | Caller получает конкретное направление и сохраняет исполнение |
| CON-01, CON-02 | Plugin skill и фиксированные spawn arguments | Fresh discovery и фактические model/effort child |
| CON-03, CON-08 | Отбор вызова в SKILL.md | Нет автоматического вызова из Astra, нет повторов без новых оснований |
| CON-04 | consultant-role.md | Нет изменений файлов/систем, child не делегирует |
| CON-05, CON-06 | Compact request и роль | Совет опирается на наблюдения и предлагает различающую проверку |
| CON-07 | Caller сохраняет решение и проверку | Совет не применяется child и не подменяет acceptance |
| CON-09 | Evaluation и проверка поставки | Фактический профиль, source/cache identity, отдельные результаты испытаний |

Конкретные сценарии, доказательства и ограничения находятся в
[Evaluation](evaluation.md). Структурные проверки не заменяют behavioral smoke,
а один smoke не доказывает экономию на реальных задачах.
