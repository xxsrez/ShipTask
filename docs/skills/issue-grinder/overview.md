# Issue Grinder: обзор

Статус: действующий пользовательский Overview, 2026-09-02.

Этот документ определяет общий смысл Issue Grinder: что это за сущность, для
кого она существует и зачем мы её разрабатываем. Он принадлежит пользователю и
меняется только по его явному указанию. Конкретные обязательные свойства
находятся в Requirements, а способ их достижения — в Architecture.

Issue Grinder — skill для автономной разработки и доставки больших сложных
изменений. Он принимает однозначно выбранный в Task Manager объём работы —
отдельную задачу, Release или Project scope — и ведёт его от незавершённого
состояния до реализованного и проверенного результата. В этот путь могут входить
разработка, интеграция, тестирование, выпуск и, когда это входит в заданные
границы, развёртывание продукта.

Skill предназначен для человека или команды, которым нужно передать агенту не
отдельный шаг программирования, а крупный результат целиком. Он рассчитан на
длинную сложную работу с множеством связанных задач, технической
неопределённостью и проблемами, возникающими уже по ходу исполнения.

Пользователь задаёт желаемый результат, объём работы и существенные границы.
После этого Issue Grinder удерживает общую цель, принимает необходимые
инженерные решения, организует исполнение, исправляет обнаруженные проблемы и
продолжает работу самостоятельно. Участие человека должно требоваться лишь в
исключительных случаях, когда без его решения или полномочия действительно
нельзя двигаться дальше.

Назначение Issue Grinder — сделать практически автономную разработку,
автоматический выпуск и развёртывание повседневным способом работы. Человек
определяет, что нужно получить, и сохраняет контроль над существенными
границами; skill берёт на себя основную сложность и возвращает готовый
проверенный результат, а не только код, план или отчёт о попытке.
